# 界面设计（REQ-260930155231-0862）

> 可视化配套见 [prototype.html](prototype.html)（每个功能点一个锚点区块）。
> 本份只管界面结构与交互；报文与数据契约见 [interfaces.md](interfaces.md) / [data-model.md](data-model.md)。

## TL;DR `serves: FR-2, FR-8`

- **一个设置页**（`settings.section`，order 21，标题「Webhook 通知」）：左侧**渠道 rail（带 app 图标）** + 右侧**目标详情卡**。
- **布局沿用 dsh-im 的成熟模式**（左栏按渠道分组、右栏是所选对象的完整配置卡）——不另造一套交互习惯。
- **失败要可见**：保存失败、投递失败、版本冲突都在界面上说清原因（不学"只打 console"）。

## 页面与入口 `serves: FR-2`

| 项 | 值 |
|---|---|
| 插槽 | `settings.section`（list，scope root） |
| 注册参数 | `{ name: 'settings.section', id: 'dsh-notice-webhook', order: 21, label: () => t('section.title') }` |
| ownerProps | `{ close: () => void }`（宿主持有面板开合） |
| 入口位置 | 设置 → 侧栏紧随「Agent 预设」（现有 order：account −10 / general 0 / models 10 / plugins 15 / agent-presets 20） |
| 为什么不挂侧栏面板 | 这是**配置**不是**工作区**；设置页是 DSH 里配置的默认归宿 |

**左右栏的分工（为什么不只是"一个表格"）**：

| 栏 | 承担 | 理由 |
|---|---|---|
| 左：渠道 rail | 按**渠道**分组浏览 + 数量徽标 + 默认组成员单独一段 | 目标天然按 app 分组；数量徽标一眼看出"哪个 app 还没配" |
| 右：详情卡 | 所选目标的**完整**配置（身份、地址、凭据、事件、默认组、最近投递） | 换地址/换事件只动一处，不必在窄表格里挤列 |

**为什么 app 图标要进 rail**：使用者是靠"图标+颜色"秒认渠道的（截图里的参考实现同理）；也避免"企业微信 / 企业微信应用"这类同名渠道看混。

### 会话绑定页（第二个标签）`serves: FR-5`

**为什么要有这一页**：目标页只能回答"这个目标被谁用"，回答不了**"这个会话绑了哪些 webhook、怎么解绑"**。而绑定最常出的问题恰恰是"某个会话收不到/发错地方"——需要按**会话**看。

```
┌─ 设置 › Webhook 通知 › [ 目标 ] [ 会话绑定 ] ─────────────────────────────────┐
│ 会话（3 条绑定）                                     [按会话标题搜索…]      │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 会话                         绑定的 webhook                    操作       │ │
│ │ 修复登录 bug（session-b7c5…） ▣项目群-企微  ▣我的手机(Slack)   [解绑]    │ │
│ │ 打包发布（session-3a91…）     ▣值守群-钉钉                     [解绑]    │ │
│ │ 数据迁移（session-77cc…）     ⚠ 目标已删除（回落默认组）        [清理]    │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│ 说明：绑定是**替代**默认组——绑了就不再发默认组；解绑后立刻回落默认组。        │
└───────────────────────────────────────────────────────────────────────────────┘
```

| 列 | 内容 | 取值来源 |
|---|---|---|
| 会话 | 标题（有则显示）+ 会话 id 尾串 | `BindingView.sessionTitle` |
| 绑定的 webhook | 目标 chips（渠道图标 + 名称）；停用的加灰标"已停用" | `BindingView.targets[]` |
| 操作 | `解绑`（清空该会话全部绑定）；目标已被删时显示 `清理`（清掉悬空引用） | RPC `bindings/delete` |

**空态**：没有任何绑定 → 「还没有会话绑定。绑定由其他插件（如看板）在它们的界面里发起，也可以在它们的弹框里用我们的选择器。」

**这一页只做两件事**：看绑定、解绑。**不做**新建绑定（新建需要知道"绑哪个会话"，那是宿主界面的上下文，硬塞进这一页反而别扭）。



| 组件 | 职责 | 关键 props |
|---|---|---|
| `SectionPanel` | 容器：拉状态、分发动作、展示全局错误 | `state`（来自 RPC） |
| `ChannelRail` | 左栏：渠道分组、数量徽标、默认组段、"新增目标"入口 | `targets`, `selectedId`, `onSelect`, `onCreate` |
| `ChannelIcon` | 渠道图标（内联 SVG，品牌色 + 简化形状） | `channel`, `size` |
| `TargetCard` | 右栏详情卡：身份 / 地址 / 凭据 / 事件 / 默认组 / 最近投递 / 底部动作 | `target`, `secrets`, `outcomes` |
| `TargetPicker` | **可嵌入选择器**：目标复选列表 + 默认组标记 + 空态引导；供其他插件的弹框复用（不自己开弹框） | `sessionId?`, `selected`, `onConfirm`, `onCancel?`, `readOnly?` |
| `BindingTable` | **会话绑定页**：会话 → 目标 chips → 解绑；含悬空引用（目标已删）的清理态 | `bindings`, `onUnbind` |
| `EventFilterGrid` | 事件复选网格（带字段名小字，空 = 全收） | `value`, `onChange` |
| `GlobalSwitches` | 总开关 + 超时/重试/冷却（volatile 配置写入） | `defaults` |
| `OutcomeList` | 最近 N 次投递结果（时间 / ✓✗ / 原因） | `outcomes` |
| `InlineError` | 行内错误与提示（校验失败、落盘失败、版本冲突） | `message`, `onRetry` |

**渠道驱动的字段可见性**（避免"填了无效字段"）：

| 渠道 | 地址 | 加签密钥引用 | 自定义头 |
|---|---|---|---|
| 企业微信 / Slack / Discord | 必填 | — | — |
| 飞书 / 钉钉 | 必填 | 选填（填了即开启加签） | — |
| 通用自定义 | 必填 | — | 选填（键值对） |

## 交互流程 `serves: FR-2, FR-8`

### 新增目标 `serves: FR-2, FR-8`

```
点左栏「+ 新增目标」
   → 右栏切到空表单（默认渠道=企业微信，rail 上高亮"未保存"）
   → 选渠道（字段随之出现/隐藏；图标同步切换）
   → 填地址（失焦即校验 http/https）
   → [保存] ──成功──▶ rail 数量徽标 +1，右栏切到新目标的详情
              └─失败──▶ 行内错误：原因 + 保留已填内容
```

### 发送测试 `serves: FR-2, FR-8, FR-10`

```
点「发送测试」→ 按钮 loading
   → RPC /test（只打一条固定测试通知，不改清单）
   → 成功：卡片顶部 ✓ + 「最近投递」顶部插入一条
   → 失败：✗ + 原因（HTTP 状态 / 业务 errcode / 网络）
```

### 编辑 / 删除 / 启停 `serves: FR-2`

| 动作 | 交互 |
|---|---|
| 编辑 | 直接在详情卡里改（无独立编辑态页面）；保存同新增 |
| 启停 | 卡片右上角开关，立即保存（乐观更新 + 失败回滚） |
| 删除 | 二次确认（"删除后引用该目标的会话绑定会失效"）；确认后保存 |

### 解绑（会话绑定页）`serves: FR-5, FR-6`

```
点某行「解绑」
   → 行内二次确认：「解绑后该会话改为发默认组（N 个目标），确认？」
   → POST /bindings/delete { revision, sessionId }
      ├─ 成功 → 行消失（或标记为"未绑定"）；顶部轻提示"已解绑，该会话已回落默认组"
      ├─ 409  → 提示"已被其他页面修改，已刷新"（与目标页同口径）
      └─ 404  → 说明该绑定已不存在 → 刷新列表即可
```

### 宿主嵌入选择器（其他插件的界面怎么用）`serves: FR-5, FR-2`

```
宿主（例如看板）在自己的弹框里：
   打开「绑定会话到 Webhook」弹框（弹框外壳是宿主的）
      └─ 挂 picker.renderTargetPicker({ sessionId, selected, onConfirm })
            用户在复选列表里勾目标（含"默认组"标记、空态引导）
            [确定] → onConfirm(ids)  → 宿主调 bindTargets(sessionId, ids)
            [取消] → onCancel()      → 宿主关闭弹框，不改绑定
```

| 分工 | 谁做 | 为什么 |
|---|---|---|
| 弹框外壳（开关/标题/按钮/位置） | **宿主** | 各宿主的交互习惯不同（看板要抽屉、别处要模态），我们不该统一 |
| 目标列表与勾选语义 | **我们**（`TargetPicker`） | 目标清单只有一份事实源；"默认组""凭据脱敏""没目标怎么办"的语义必须同源 |
| 绑定写入 | 宿主调我们的 Host Service `bindTargets` | 写成败与版本栅栏都在 Host 侧统一 |

**降级**：宿主检测不到 `dshNoticeWebhookClient`（或 `version !== 1`）时，**不显示绑定入口**——而不是显示一个点了没反应的按钮。

```
保存 → 409（revision 过期）
   → 顶部提示「配置已被其他页面修改，已为你刷新到最新」
   → 自动重拉状态；用户已改的字段**保留在表单里**，由用户决定是否再次保存
```

## 状态与边界 `serves: FR-2, FR-8`

| 状态 | 界面表现 |
|---|---|
| 加载中 | 骨架（rail + 卡片占位），**不显示空态** |
| 空清单 | 右栏引导：「还没有目标。点「+ 新增目标」，或直接配 `webhookUrl` 用兜底通道。」 |
| 左栏有渠道、右栏无选中 | 右栏提示「从左侧选一个目标，或点「+ 新增目标」」 |
| RPC 不可达 | 整页错误态 + 重试（**不显示成空清单**——会误导用户以为配置丢了） |
| 保存失败（校验） | 行内错误 + 原因（如"地址必须是 http/https"） |
| 保存失败（落盘） | 顶部错误：「配置未写入（文件不可写）」，列表**不**改变 |
| 删除后绑定失效 | 删除确认里写明；删除后引用该 id 的会话视为未绑定，不报错 |

## 凭据展示规则 `serves: FR-7`

| 场景 | 显示 |
|---|---|
| 未配置密钥 | 输入框空 + 占位「凭据引用名（如 DINGTALK_SECRET）」 |
| 已配置密钥 | 只显示引用名 + 「已配置」标记；**不显示值** |
| 清除密钥 | 清空引用名即关闭加签（不需单独按钮） |

界面**从不**展示密钥明文，也**不提供**"查看明文"入口。

## 文案与本地化 `serves: FR-2`

- 全部可见文案走客户端 `locale` 服务（`ctx.locale.bind('dsh-notice-webhook')`）；
- `label` 用 **thunk** 注册，DSH 切语言时会重新读取；
- 渠道名用**渠道自己的**本地化文案（与左栏图标一致），英文缺失回落中文。

## 主题与样式约束 `serves: FR-2`

| 约束 | 做法 |
|---|---|
| 只跟随主题 | 颜色/圆角/间距用主题 token；**渠道图标是唯一允许带自有配色的元素**（品牌色是识别的一部分） |
| 不抢宿主样式 | 不写全局选择器；组件内样式随卸载消失 |
| 亮/暗都可读 | 两种主题检查对比度；选中态用 token 高亮而非硬编码底色 |
| 不替换根节点 | 只在 `settings.section` 的内容列里渲染 |

## 与 RPC 的映射 `serves: FR-2, FR-8`

| 界面动作 | RPC | 成功后 |
|---|---|---|
| 打开页面 / 重试 | `GET /state` | 渲染 rail + 卡片 + `defaults` + `outcomes` |
| 保存目标 | `POST /targets` | 用返回的 `targets` 替换本地列表 |
| 删除目标 | `POST /targets/delete` | 同上 |
| 启停切换 | `POST /targets`（同保存） | 同上 |
| 发送测试 | `POST /test` | 卡片内结果 + 刷新 `outcomes` |
| 改全局开关 | volatile 配置写入（`config-form` 的 `set`） | 立即生效，无需刷新 |

## 原型锚点 `serves: FR-2, FR-4, FR-5`

| 功能点 | 原型区块 | 看什么 |
|---|---|---|
| FR-2 界面管理目标清单 | `prototype.html#FR-2` | 左 rail + 右详情卡；新增表单；空态；保存失败 |
| FR-4 逐目标事件过滤 | `prototype.html#FR-4` | 事件复选网格（带字段名小字、全收提示） |
| FR-5 窗口绑定多目标 | `prototype.html#FR-5` | 左栏「默认组」段 + 卡片里的"谁在用"标记 + **宿主弹框里嵌入的选择器** + **会话绑定页（绑定列表 / 解绑）** |

**原型是草图不是交付物**：图标为**内联 SVG 近似标记（非官方素材）**，定稿后可替换为正式素材；布局与交互路径才是本原型要定的东西。

## 验收口径 `serves: FR-2, FR-8`

```sh
# 1) 页面可打开（人工）：刷新 DSH 页面 → 设置 → 侧栏应出现「Webhook 通知」
# 2) 表单校验不落盘（人工 + 文件）：
grep -c '"version": 1' "$DSH_HOME/state/dsh-notice-webhook/targets.json"   # 校验失败时应为 0 或文件不存在
# 3) 保存即时生效（人工）：新增目标 → 不重启 → 触发一条通知 → 目标收到
# 4) 冲突可见（人工）：两个页面同时编辑 → 后保存者看到"已被其他页面修改"
```
