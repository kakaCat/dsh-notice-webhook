# 前端设计（以原型为唯一视觉规格）

> **TL;DR**：目标态 = `prototype.html` 帧 1／3 的**逐元素复刻**；本页给出每个元素的尺寸、文案与状态，
> 以及"现状差在哪"的逐元素对照表。图标取 dsh-im 品牌 logo；新增「只填 key」与「? 说明浮层」两处交互。

## 2. 左栏 rail 规格（serves: FR-1, FR-4, FR-5）

| 段 | 内容 | 徽标 |
|---|---|---|
| 顶部 | 「全部目标」 | 目标总数 |
| `按渠道` | 六个渠道固定出现（**即使 0 个也显示**）+ 每组图标与名称 | 该渠道目标数 |
| — | 「+ 新增目标」（点击 → 新建态，默认渠道为第一个） | — |
| `默认组 · 未绑定目标的会话发这里` | `isDefault === true` 的目标 | `默认` |
| `不在默认组` | 其余目标 | `绑定`（该目标被某会话绑定时）／空 |

| 属性 | 值 |
|---|---|
| 宽度 | 196px（窄屏 168px） |
| 行高 | 28px；行内 gap 8px；图标 16px |
| 选中态 | 背景 `--dsh-hover`，左侧 2px accent 竖条 |
| 分组标题 | 12px、次级色、上间距 10px |

## 3. 详情卡规格（serves: FR-2, FR-3, FR-4, FR-5）

**card-head**：图标 22px + 名称（15px 600） + `id: <targetId>`（12px 次级） + 右侧 `启用` 文案 + 开关。

| 段 | 字段 | 控件与文案 | hint |
|---|---|---|---|
| 基本 | 名称 | input | 给人看，60 字内 |
| 基本 | 渠道 | select（选项带 `▣` 前缀） | 决定报文格式与成功判定 |
| 基本 | **地址/密钥** | `input:'key'` 渠道 → 单个 key 输入框 + `[发送测试]` + `怎么拿 key?`；`input:'url'` 渠道 → 完整地址输入框 | 按 `channelMeta.keyLabel` 显示 label |
| 基本 | 加签密钥 | input + `已配置` chip（`secretConfigured`） | 只存凭据引用名，界面不回显密钥值 |
| 关心事件 | 四项 2×2 网格 | 顺序固定：**对话完成**(turn/end) → **等待回答**(ask_user_question) → **等待授权**(approval/asked) → **目标终态**(goal/*)，每项带字段名小字 | 一个都不勾 = 全收 |
| 归属 | 默认组 | 开关 + hint「未绑定任何目标的会话会发给默认组里的目标」 | — |
| 归属 | **谁在用** | chips：`默认组`（当 `isDefault`）+ `会话 X（绑定）`（当有会话绑它）+ hint「只读展示，便于排查"某个会话为什么没收到"」 | **只读**，不可在此改绑定 |
| 观测 | 最近投递 | 每行：时间 + `✓200`/`✗200 errcode 310000` + 原因 | 每目标保留最近 5 条（重启清空） |
| 动作 | — | `[删除目标]`（左、danger） … `[保存]`（右、primary） | — |

**删除的二次确认**：`确认删除目标「<名称>」？删除后绑定它的会话会回落默认组。`

## 4. 图标规格与来源（serves: FR-1）

| 渠道 | 图标来源 | 品牌色 |
|---|---|---|
| `wecom` | dsh-im `WecomLogoGlyph` | 企微绿（沿用 glyph 内的 fill） |
| `feishu` | dsh-im `FeishuLogoGlyph` | `#00D6B9` / `#1456B8` / `#3370FF` 三色 |
| `dingtalk` | dsh-im `DingtalkLogoGlyph` | 钉钉蓝 |
| `slack` | dsh-im `SlackLogoGlyph` | `#36C5F0/#2EB67D/#ECB22E/#E01E5A` |
| `discord` | dsh-im `DiscordLogoGlyph` | `#5865F2` |
| `custom` | 自有中性图标（dsh-im 无对应） | 次级色 `currentColor` |

| 规则 | 说明 |
|---|---|
| 取用方式 | **逐字复制** dsh-im 的 `path` 数据与其 `viewBox`、`fill`；不改形状、不重绘 |
| 复用 | rail 16px、card-head 22px、选择器 14px——同一组件带 `size` |
| 署名 | 代码注释标明 `取自 dsh-im plugin-src/client/channel-logos.js#<GlyphName>`；`THIRD_PARTY_NOTICES` 记一条来源 |
| 禁 | 不引远程图片、不加 base64 大图、不引入图标库依赖 |

## 5. 说明浮层（serves: FR-3）

```
┌ 怎么拿企微机器人 key ─────────────────────┐
│ 1. 在企微群里点「…」→ 群机器人 → 添加     │
│ 2. 复制 Webhook 地址里 key= 之后的部分    │
│ 3. 粘贴到左侧输入框并保存                 │
│                        官方文档 ↗         │
└───────────────────────────────────────────┘
```

| 契约 | 规定 |
|---|---|
| 触发 | 点 key 输入框右侧 `?`（或字段 label 旁的 `ℹ`）；再次点击或点空白收起 |
| 形态 | **就地展开**（popover），不跳页、不开新窗、不用浏览器弹窗 |
| 内容 | 标题 + 有序步骤 + `官方文档 ↗`（新窗口打开 `docUrl`）；内容来自 `channelMeta.help` |
| 缺失 | `help` 不存在时不渲染入口（不留空面板） |
| 无鼠标 | 键盘可达（`button` + `aria-expanded`），Esc 关闭 |

## 6. 会话绑定页（serves: FR-5）

| 元素 | 规格 |
|---|---|
| 表格列 | `会话`（标题 + id 尾串）／`绑定的目标`（chips，复用图标）／`操作`（`[解绑]`） |
| 悬空引用 | 目标已删 → chip 标红，后缀「（目标已删除）」；行尾 hint「解绑后该会话回落默认组」 |
| 解绑 | 二次确认「解绑后该会话改为发默认目标组，确认？」 |
| 空态 | 「还没有任何会话绑定」+ 一句引导（宿主插件可用可嵌入选择器绑定） |

## 7. 与现状的逐元素差距（serves: FR-4, FR-5）

| 元素 | 原型 | 现状 | 本次动作 |
|---|---|---|---|
| content-head | `设置 › Webhook 通知` + `[全局设置] [打开配置文件]` | **没有** | 补 |
| card-head | 图标 + 名称 + `id:` + `启用` 文字 + 开关 | 只有名称 + 图标 | 补 id 与启用文字/开关位置 |
| rail 结构 | 三段（全部目标／按渠道分组／默认组 + 不在默认组） | 平铺目标列表 | 重排 |
| rail 徽标 | 数量徽标 + `默认`/`绑定` | 只有「停」标记 | 补 |
| 图标 | 品牌色 glyph | 单色 path | 替换 |
| 地址字段 | 只填 key + `[发送测试]` + `怎么拿 key?` | 填完整 URL，测试按钮在底部 | 改 |
| 加签字段 | input + `已配置` chip | input + 长 hint | 改 |
| 事件网格 | 2×2，顺序 完成/提问/授权/目标终态 | 2×2，顺序 完成/授权/提问/目标终态 | 调序 |
| 谁在用 | chips（默认组／会话 X（绑定）） | **没有** | 补 |
| 最近投递 | 时间 + ✓/✗ + 状态码 + 原因 | 有，但缺 ✓/✗ 与码的分列 | 改 |
| 动作区 | 删除在左、保存在右（primary） | 保存/测试/停用/删除平铺 | 重排 |
| 绑定页 | 表格 + chips + 悬空标红 | 已实现 | 复用新图标与样式 |

## 8. 状态矩阵（serves: FR-4）

| 状态 | 表现 |
|---|---|
| 加载中 | 卡片区骨架 + 「加载中…」，rail 不闪 |
| 读取失败 | 顶部条错误 + `[重试]`，保留上一次渲染 |
| 无目标 | rail 只剩「按渠道」与「+ 新增目标」；卡片区给一句起步引导 |
| 目标是停用 | card-head 的开关关闭 + rail 行次级色 |
| 会话悬空绑定 | 绑定页 chip 标红（§6） |
| 多页面并发写 | `409` → 顶部提示 + 刷新 + **保留用户已填内容** |
