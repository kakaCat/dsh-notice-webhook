# 用户场景

> **TL;DR**：五个场景——首次配置（只看 key）、改地址（回填 key）、老配置升级（照旧投递）、
> 插件回滚（旧版本仍能投）、宿主插件接入（选择器不变）。场景只描述"人看到什么、结果如何"。

## 场景总览（serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6）

| 编号 | 角色 | 场景 | 涉及 FR | 可观察结果 |
|---|---|---|---|---|
| UC-1 | 首次配置的用户 | 从企微群里复制一段 key，贴进设置页 | FR-1, FR-2, FR-3, FR-4 | 只填一个框就保存成功；旁边能点开"怎么拿 key" |
| UC-2 | 多目标用户 | 一眼看清"哪个渠道配了几个、哪个是默认" | FR-1, FR-4, FR-5 | rail 按渠道分组带数量徽标；默认组独立成段 |
| UC-3 | 老用户 | 升级插件后啥也没改，通知照旧到 | FR-6 | 老 `targets.json` 被自动升级；会话照旧收到 |
| UC-4 | 运维 | 把插件回滚到上一版 | FR-6 | 旧版本读新文件不报错、仍能投递 |
| UC-5 | 宿主插件开发者 | 在自己弹框里让用户选 webhook | FR-1, FR-5 | 选择器外观与设置页一致；契约与返回值不变 |

## UC-1 首次配置：我只有一个 key（serves: FR-2, FR-3）

```
用户在企微群里加了机器人，拿到一段 key（形如 693a91f6-…）
   │
   ├─ 打开 设置 → 通知 → 点「+ 新增目标」→ 选「企业微信」
   ├─ 界面只问：[机器人 key] （不是整条 URL）
   ├─ 不确定 key 从哪拿 → 点字段旁的 ? → 就地展开三步说明 + 官方文档链接
   └─ [保存] → 卡片顶部出现该目标；rail「企业微信」徽标 0 → 1
```

**结果**：用户**不需要理解 URL 结构**，也不需要手动拼 `?key=`；拼装由 Host 按渠道前缀完成。

## UC-2 多目标：一眼看清渠道分布（serves: FR-1, FR-4, FR-5）

```
开启页面
   ├─ rail：全部目标 3 ／ 按渠道（企微 1、钉钉 1、飞书 0、Slack 1、Discord 0、通用 0）／ 默认组（2 个带「默认」）
   └─ rail「不在默认组」：我的手机（Slack）——带「绑定」徽标
```

**结果**：0 个的渠道也在（知道"这个渠道我还没配"）；默认组与绑定状态不用展开卡片就能看见。

## UC-3 老配置升级：我什么都没改（serves: FR-6）

```
插件升级后第一次启动
   ├─ 读到 v1 的 targets.json（只有 url）
   ├─ 按渠道前缀反解出 key：企微/钉钉/飞书三条成功 → 升 v2 落盘
   ├─ 一条用户手改过 url（前缀不匹配）→ 保留 url 直投 + 日志一条 warn
   └─ 通知照旧送达（用户无感）
```

**结果**：**升级不改配置**；反解不了的条目也不会静默失效（有 warn、行为退化为原样直投）。

## UC-4 回滚：退回上一版插件（serves: FR-6）

```
回滚到旧版本
   ├─ 旧版本读 v2 文件：忽略不认识的 key 字段
   ├─ 仍然从 url 取到地址（派生值已落盘）
   └─ 投递照常
```

**结果**：回滚**不丢投递能力**；这就是"v2 里同时保留派生 url"的存在理由。

## UC-5 宿主插件接入：选择器长相要一致（serves: FR-1, FR-5）

```
宿主（如看板）在自己的弹框里：
   ├─ 取 dshNoticeWebhookClient.v1
   ├─ renderTargetPicker({sessionId, selected, onConfirm})
   │     └─ 列表项带与设置页同款品牌图标与渠道名
   └─ 用户勾选 → onConfirm(ids) → 宿主调 Host Service bindTargets 落库
```

**结果**：两处界面观感一致；选择器**契约与返回值不变**（v1），宿主无需改动。
