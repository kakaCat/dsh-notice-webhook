# 用户场景

> **TL;DR**：五个场景——后台跑长活（不该叫）、安静模式结算（必须叫）、常驻 job 之后的普通问答（照旧叫）、
> 排障一键回到旧行为、卸载回滚。场景只描述「人看到什么、结果如何」。

## 场景总览（serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6）

| 编号 | 角色 | 场景 | 涉及 FR | 可观察结果 |
|---|---|---|---|---|
| UC-1 | 开发者 | 让 agent 后台跑全量测试，自己去开会 | FR-1, FR-3, FR-5 | 开会期间**不再**收到「会话已完成」；测试跑完 agent 收尾后才收到一条 |
| UC-2 | 用安静模式的用户 | 关掉了 agent 自动唤醒（`completionDelivery: 'quiet'`） | FR-3 | job 结算时**一定**收到一条完成通知（不会因为没人唤醒 agent 就永远静默） |
| UC-3 | 挂着 dev server 的会话 | 后台常驻一个 dev server，之后照常问答 | FR-2 | 每轮结束照旧收到完成通知（常驻 job **不**把该会话永久静音） |
| UC-4 | 排障者 | 怀疑「最近没收到完成通知」是本判定导致 | FR-4, FR-6 | 看板 `drop` 原因码一眼看到 `job-running`；改配置一键回到旧行为做对照 |
| UC-5 | 运维 | 卸载/回滚插件 | FR-4, FR-5 | 卸载即净（零落盘变更）；旧版本行为逐条一致 |

## UC-1 后台跑长活：别在活还没干完时叫我（serves: FR-1, FR-3, FR-5）

```
你说：跑一遍全量测试，跑完告诉我
   │
   ├─ agent 以 run_in_background 起 bash job（返回 job id），本轮结束
   │     └─ 插件：本会话还有未结算的 job → 不推「会话已完成」（日志记 job-running）
   ├─ 你去开会（期间什么都没有）
   ├─ 测试跑完 → DSH 唤醒 agent → agent 读结果、汇报 → 本轮结束
   │     └─ 插件：本轮没有未结算 job → 推「会话已完成」（**唯一**一条）
   └─ 你回来：通知说的「完成」是真的完成
```

**结果**：从「两次通知、第一次是假的」变成「一次通知、内容为真」。

## UC-2 安静模式：不能因为没人唤醒 agent 就永远不叫我（serves: FR-3）

```
配置：tool-jobs 的 completionDelivery = 'quiet'（或唤醒预算 maxConsecutiveWakes 用尽）
   │
   ├─ 后台 job 本轮结束 → 插件抑制（不推）
   ├─ job 结算 → DSH 只把完成通知放进 agent 收件箱，**不开新轮次**（没有 turn/end）
   └─ 插件宽限窗口（1.5s）到点、该会话仍空闲 → 补发一条「会话已完成」
```

**结果**：抑制不会变成漏报——这正是选择「抑制 + 兜底补发」而不是「只抑制」的原因。

## UC-3 常驻 job：别把我这个会话永久静音（serves: FR-2）

```
某天：agent 后台起了一个 dev server（一直 running，不结算）
今天：你问了一句「这个函数干嘛的」→ agent 答完，本轮结束
   │
   └─ 插件：running 的 job 是**很多轮之前**拉起的（startedAt 早于本轮 turn/start）
         → 不参与判定 → 照旧推「会话已完成」
```

**结果**：常驻 job 只影响**拉起它的那一轮**，不会让该会话此后的通知全部消失。

## UC-4 排障：先看原因码，再一键回到旧行为（serves: FR-4, FR-6）

```
「怎么没收到完成通知？」
   ├─ 看 Host 日志 → drop 原因码 job-running（带被抑制的 job id）
   │     └─ 结论：不是漏发，是后台 job 还没结算
   ├─ 仍想验证旧行为 → 插件配置 jobAwareComplete: false（**热改，不重启**）
   │     └─ 下一次 turn/end 立即照旧推送
   └─ 排查完改回 true（同样不用重启）
```

**结果**：误判与「真漏发」一眼可分；对照实验零成本。

## UC-5 卸载回滚：不留残留（serves: FR-4, FR-5）

```
卸载/回滚本版本
   ├─ 没有新增落盘文件、没有新增落盘键（targets.json / bindings.json 原样）
   ├─ 组合里没有 job 服务时也照常工作（自动降级 + 一条 warn）
   └─ 出站报文与旧版本逐字段一致 → 接收端无需任何改动
```

**结果**：回滚不丢能力、不改接收端、不残留状态。
