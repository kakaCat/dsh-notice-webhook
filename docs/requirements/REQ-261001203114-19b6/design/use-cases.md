# 用户场景

> **TL;DR**：七个场景——报错停下（必须叫）、崩溃中断（必须叫）、自己按 Esc（不许吵）、无人值守的自动轮里报错（必须叫）、
> 只想收完成通知的人（安静，且绝不再收到假「已完成」）、老用户升级（什么都不用做也别漏）、排障与回滚。
> 场景只描述「人看到什么」，机制见 [interfaces.md](interfaces.md)。

## 场景总览（serves: FR-1, FR-2, FR-3, FR-4, FR-5, FR-6）

| 编号 | 角色 | 场景 | 涉及 FR | 可观察结果 |
|---|---|---|---|---|
| UC-1 | 开发者 | 模型流报错，agent 停下 | FR-1, FR-2, FR-3 | 收到「会话异常中断（MALFORMED_RESPONSE）」 |
| UC-2 | 开发者 | 会话崩溃后被事后收尾 | FR-1, FR-3 | 收到「会话异常中断」 |
| UC-3 | 开发者 | 自己按 Esc 停掉本轮 | FR-1, FR-6 | **安静**（debug 日志可见原因码） |
| UC-4 | 值守者 | 自动轮里 agent 报错停住 | FR-1, FR-4 | 收到中断通知（不被自动轮静默） |
| UC-5 | 只想收完成的人 | 关掉中断通知 | FR-4 | 中断安静；**且不会收到假「已完成」** |
| UC-6 | 老用户升级 | 什么都不配 | FR-5 | 既有目标照旧收到中断通知，无需手动勾选 |
| UC-7 | 维护者 | 排查「为什么没收到」 | FR-5, FR-6 | 一条原因码日志；回滚 = 装回旧版本 |

## UC-1 模型流报错：必须叫，而且不许说「已完成」（serves: FR-1, FR-2, FR-3）

- **场景**：agent 跑着一轮，provider 流里出现 `tool input is invalid JSON`（`MALFORMED_RESPONSE`，默认不重试）→ 本轮以 `error` 收尾，agent 停下。
- **改前（实测）**：收到「会话已完成」→ 人以为活干完了，切回来发现停在半路。
- **改后**：收到「修复登录 bug · 会话异常中断（MALFORMED_RESPONSE）」，`custom` 接收端还能拿到 `error.message` 全文（单行、≤200 字符）。
- **可观察结果**：报文 `event === 'turn/error'`；**同一轮绝不出现** `event === 'turn/end'`。

## UC-2 崩溃中断：孤儿 turn 收尾要叫人（serves: FR-1, FR-3）

- **场景**：进程/会话异常结束，重启后 DSH 给那个没结束的 turn 补写 `turn/end(interrupted)`。
- **改前**：静默丢弃（默认 `skipReasons` 含 `interrupted`）→ agent 中断不工作，人完全不知。
- **改后**：收到「… · 会话异常中断」（无括号后缀，因为 `interrupted` 没有错误码）。

## UC-3 自己按的 Esc：不许吵（serves: FR-1, FR-6）

- **场景**：用户主动取消本轮（`aborted`）。
- **结果**：安静——这正是「自己知道的事不用被通知」；debug 日志留一行 `turn-aborted`，排障时能确认「是规则静默的，不是投递失败」。
- **注意**：即使把 `aborted` 从 `skipReasons` 移除，`aborted` **仍然安静**（它天然归入「不叫也不谎报」），避免误以为改配置能打开它。

## UC-4 自动轮里报错：无人值守时更要叫（serves: FR-1, FR-4）

- **场景**：goal / dive 模式让 agent 连续自动跑；某一轮里 provider 报错，链断在这里。
- **改前**：自动轮被整体静默（`autoRound`），加上 `error` 被当完成 → 要么没声，要么错报。
- **改后**：中断通知**不受自动轮静默影响**（静默只对「完成」生效）；同轮的 `completed` 依旧安静，避免吵人。

## UC-5 只想收完成通知：安静，但不许被喂假消息（serves: FR-4）

- **场景**：用户觉得中断提醒吵，关掉 `notifyInterrupt`（或在 `skipReasons` 里加 `error`）。
- **结果**：中断一条不发；**同时也不会**回落到「当完成推」——本包不提供「退回谎报」的开关（唯一一处违背「关掉 = 回到旧行为」惯例，理由写在需求 FR-4）。

## UC-6 老用户升级：什么都不用配，也不许漏（serves: FR-5）

- **场景**：升级前用界面建过目标（当时「全选」把四项写成了显式列表）。
- **风险（若不处理）**：新事件 `turn/error` 不在那份白名单里 → 中断通知被目标级过滤**全部丢掉**，且用户毫不知情。
- **改后**：载入时把「恰等于旧版全集」的记录归一化为**全收**（`events: []` + `eventsMode: 'all'`）→ 开箱即收；
  而**主动取消勾选**「会话中断」的用户（保存后恰好也是四项）带 `eventsMode: 'explicit'`，**关得掉**。

## UC-7 排障与回滚（serves: FR-5, FR-6）

- **场景**：用户问「我明明记得 agent 报错了，怎么没收到？」
- **排查**：看 Host debug 日志的 `turn-*` 原因码（`turn-skipped` / `turn-aborted` / `turn-not-notifiable`），
  再看设置页该目标的「关心事件」勾选与 `notifyInterrupt` 开关；`custom` 目标还能看「最近投递」。
- **回滚**：装回旧版本插件即可——`targets.json` 的 `version` 未变，旧版本读同一份文件照常工作（多余的 `eventsMode` 被忽略）。
