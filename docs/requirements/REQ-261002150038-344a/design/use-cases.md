# 用户场景（REQ-261002150038-344a）

> 本文档承载需求文档放不下的**多角色 / 多分支场景**：谁在什么情形下该被叫、什么情形下必须安静。
> UC 编号供 `test-cases.md`（被测对象）与任务卡（设计落点）引用。

## 场景总览 <!-- serves: FR-1, FR-2, FR-3, FR-4 -->

| 场景 | 角色 | 触发 | 完成标志 | serves |
|---|---|---|---|---|
| UC-1 | 使用者（离开电脑） | 看板 Dive 连跑 N 轮，每轮全自动 | 手机一条通知都不响（注入轮静默） | FR-1, FR-2 |
| UC-2 | 使用者（在电脑前） | 自动续跑中途自己插话一轮 | 收到 1 条「对话完成」，且「任务」= 自己那句话 | FR-1, FR-3 |
| UC-3 | 使用者（离开电脑） | Dive 轮里 agent 报错 / 崩溃中断 | 收到 1 条「⚠️ 会话中断」 | FR-2 |
| UC-4 | 群里的同事 | 飞书收到一条通知，扫一眼 | 不再看到与标题重复的「类型」行 | FR-4 |
| UC-5 | 使用者（设置页） | 编辑文案并看预览 | 卡片预览无「类型」行；纯文本预览仍有 | FR-4 |

## UC-1 自动续跑不吵人 <!-- serves: FR-1, FR-2 -->

- **用例角色**：用看板 Dive 模式跑需求的使用者（人不在电脑前，只想知道「要不要回来」）。
- **前置条件**：需求 `dive.activation === 'armed'`；通知目标已配置（绑定或默认组）；窗口处于 `implementing` 等阶段。
- **交互流程**：
  1. pmboard 向会话注入 `user/message{source:{kind:'dive', requirementId, round}}`（「继续执行需求 …（Dive 模式自动续跑，第 N 回合）」）；
  2. agent 跑完该轮 → `turn/end(reason.kind='completed')`；
  3. 通知插件判定「本轮只有注入消息、没有 direct human 消息」→ 判为注入轮 → **完成意图静默**；
  4. 第 N+1 回合重复 1–3。
- **异常流**：若中途人插话 → 走 UC-2；若中途报错 → 走 UC-3；若某轮没有任何 `user/message` → **不静默**（按普通轮推送，宁可多响不误吞）。
- **后置条件**：`GoalTracker` 的轮次标记在 `turn/end` 后被清空，不跨轮残留。
- **完成标志**：接收端在 3 个连续自动回合里收到 **0 条**报文。

## UC-2 人插话的那一轮照常响 <!-- serves: FR-1, FR-3 -->

- **用例角色**：在自动续跑窗口里插话的使用者（如 `/steer` 或直接发消息）。
- **前置条件**：同 UC-1，且本轮既出现了注入消息、也出现了 direct human 消息。
- **交互流程**：
  1. 注入的 dive 消息到达 → `sawInjected = true`；
  2. 人的消息到达（`source` 缺失或 `kind === 'user'`）→ `sawHuman = true`；
  3. `turn/end(completed)` → `isAutoRound() === false` → 正常推送；
  4. 报文「任务」字段 = **人**那句话（注入正文被 PromptTracker 挡掉）。
- **异常流**：人只发了一句但被判定为注入（kind 非 `'user'`）→ 属已知取舍（口径单点、注释与用例锁死；真发生时改 `isHumanSource` 一处）。
- **后置条件**：无（本轮通知照常入 outcome 记录）。
- **完成标志**：接收端收到 1 条 `turn/end` 报文，且 `prompt` 字段等于人的原话。

## UC-3 自动轮里出事必须叫人 <!-- serves: FR-2 -->

- **用例角色**：同 UC-1（离开电脑，但必须知道「跑挂了」）。
- **前置条件**：注入轮以 `reason.kind === 'error'`（或 `'interrupted'` / 未知 kind）结束。
- **交互流程**：
  1. 注入的 dive 消息 → `sawInjected = true`；
  2. `turn/end(reason.kind='error')` → `Classifier` 产出**中断**意图；
  3. `handle()` 的静默分支只挡 `complete` → **照常 dispatch**；
  4. 卡片标题 `⚠️ 会话中断`（正文无「类型」行，含错误码）。
- **异常流**：若 `skipReasons` 里写了 `error`（用户显式选择彻底安静）→ 静默，且 `logger.debug` 留痕——这是既有语义，本次不改。
- **后置条件**：无。
- **完成标志**：接收端收到 1 条 `turn/error` 报文。

## UC-4 飞书卡片扫读 <!-- serves: FR-4 -->

- **用例角色**：群里扫一眼通知的同事。
- **前置条件**：目标渠道为飞书；本轮确实触发推送。
- **交互流程**：
  1. 卡片标题栏给出事件（`✅ 对话完成` / `⚠️ 会话中断` / …）与配色；
  2. 正文依次给「会话 / 工作区 / 任务 / 时间」——**不再**出现「类型」行；
  3. 需跳转时底部给按钮（仅 `http(s)` 链接）。
- **异常流**：无 context 的老调用方仍发纯文本（回落路径不变）。
- **后置条件**：无。
- **完成标志**：卡片 `elements[0].fields` 里没有 `类型`；标题与其余字段顺序不变。

## UC-5 设置页预览与实际一致 <!-- serves: FR-4 -->

- **用例角色**：在「设置 → 通知」里调文案的使用者。
- **前置条件**：打开文案编辑器（`PayloadEditor` + `PayloadPreview`）。
- **交互流程**：
  1. 使用者看到「飞书卡片」区 —— **无**「类型」行（卡片标题已给事件）；
  2. 同一屏的「纯文本（企微 / 钉钉 / Slack / Discord）」区 —— **保留**「**类型**：✅ 对话完成」（文本渠道没有标题栏，这一行是唯一的事件标记）；
  3. 字段开关 / 排序 / 模板行为不变。
- **异常流**：用自定义 `template` 时不做猜测，模板内容原样展示（避免"预览替你删了一行"）。
- **后置条件**：无（预览是只读渲染，不落盘）。
- **完成标志**：两个区块的渲染树分别满足「卡片区无、纯文本区有」。
