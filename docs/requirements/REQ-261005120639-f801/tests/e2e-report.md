## 1. 链路 ①：压住 → 子代理结束 → 宽限到点 → 补发（覆盖 FR-1 / FR-2 / FR-5）

| 步骤 | 动作 | 实测断言 |
|---|---|---|
| 1 | 基线运行时：真人说一句 → `turn/end(completed)` | 接收端 **1 条**（对照组） |
| 2 | 实验运行时：真人说同一句 → `turn/start` → 派一个 `running` 的 continuable 子代理 → `turn/end(completed)` | `action:'dropped'`、`reason:'subagent-running'`、`subagentIds:['s-child']`、`jobIds:[]`；接收端**仍是 1 条**（没有新报文） |
| 3 | 子代理结束（`agents` 里不再有 running 后代）+ `observeSubagentEnd()` + 宽限到点 | 接收端 **2 条**，且第 2 条与第 1 条**逐字段相等**（忽略 `at`）——含被压住那一轮的「你说了什么」 |

**为什么这是关键证据**：过去这一步会直接发出第 2 条（假完成）；现在它只在**子代理真的结束**之后才发出。

## 2. 链路 ②：压住 → 新轮次 → 不重复（覆盖 FR-2 / FR-5）

| 步骤 | 动作 | 实测断言 |
|---|---|---|
| 1 | 同上压住一条完成通知 | 接收端 0 条新增 |
| 2 | 子代理结束 + 复检起宽限，**宽限窗口内**父会话 `turn/start`（对应 DSH 的结果唤醒） | 推进计时器后接收端 **0 条**——补发被取消，避免两条重复 |
| 3 | 该新轮次自己的 `turn/end(completed)` | 接收端 **1 条**（这一条才是真的完成通知） |
